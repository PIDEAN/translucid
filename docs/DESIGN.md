# Translucid 设计说明 · Design notes

面向贡献者的架构与关键决策说明。代码注释为英文，界面文字为简体中文。

## 总体结构

```
content script (document_idle, 所有页面)      background service worker                  扩展页面（共用 src/ui/rail.ts 左侧导航）
├─ extract  段落提取（块级 run）             ├─ session  一个标签页一个会话             ├─ 工作台 sites.html：站点列表 / 概览 / 审核 / 译文 / 记录 / 分享 / 设置
├─ serialize 占位符 <a1>…</a1> / {{n}}       ├─ routing  选服务商、ProviderGate、备用   ├─ 沉浸翻译 options.html#/immersive：显示 / 场景专家 / 术语表 / 站点规则
├─ controller 懒加载 + MutationObserver     ├─ providers OpenAI 兼容 SSE + Claude SDK  ├─ 配置 options.html#/config：服务商与路由 / 用量与缓存 / 关于与隐私
└─ render  双语 / 只看译文、布局守卫          ├─ mt  免费机翻（短文本）                    └─ popup：本地化 | 网页翻译 两个标签页
pack content script (document_start,          ├─ cache  IndexedDB 翻译缓存（LRU）
  只在有语言包的站点运行时注册)               └─ pack-*  语言包存储 / 注册 / 候选 / 生成 / 扫描
├─ applier  原地替换界面文字（按语境）
├─ learner  日常使用中记录新的界面文字
└─ picker + collect  圈选区域、收集候选
scan content script (按需注入)
└─ explorer + scan-overlay  一键扫描导航与弹层
```

所有网络请求都由 service worker 发出，API Key 不进入页面。

### 扩展页面
- 三块平级入口：工作台（站点本地化，主打功能）、沉浸翻译、配置。`src/ui/rail.ts` 渲染统一的左侧导航、页头（`pageHead`）和服务商状态；`options.html` 没有 hash 时跳到工作台。
- 界面规范集中在 `src/ui/ui.css`：控件高度 32 / 38 / 46，圆角 8 / 10 / 14，同一行的按钮和输入框同高同圆角；`.callout` 用于说明与状态，`details > summary` 统一箭头。钴蓝代表网站原本的界面，琥珀代表你的语言（待审核、译文层）。
- 页面是整页重建的（`renderAll` / `draw`），所以界面状态（折叠项、草稿、正在编辑的术语）都放在模块状态里，重建后恢复；后台数据变化时，正在输入或有未保存草稿就推迟重绘，按下鼠标期间也不重建，避免吞掉点击。
- 设置页保存时与最新存储做三方合并（`src/ui/settings-merge.ts`，数组按 id / host 合并），不会覆盖弹出菜单或后台刚写入的设置。
- 网页上的圈选面板和扫描浮层在 shadow DOM 里，使用同一套颜色和尺寸；所有可信输入在 window 捕获阶段拦下，面板动作直接执行，不会以任何形式（包括焦点变化）传到网页，所以网页上展开的菜单不会被关掉。

## 网页翻译

### Prompt 分层
- **协议层**（`src/prompt/protocol.ts`，代码固定，带 `PROTOCOL_VERSION`）：输出格式 `<n>…</n>`、排版、标签规则。
- **场景专家**（`src/prompt/experts/builtin.ts`）：每个场景只写 3–7 条领域规则，带具体反例。按域名匹配，也可由页面预处理推断。
- system prompt 只随专家变化，保证服务商的前缀缓存命中；改协议文字必须把 `PROTOCOL_VERSION` 加一，它是缓存 key 的一部分。
- user 消息依次是：命中的术语、页面上下文（标题 + 一句话主题）、本批段落。上下文放在任务之前，并标明只读。

### 批处理与调度
- 实时翻译每批只调用一次模型；「翻译 → 自查 → 改进」只用于手动精翻。
- 首批小（约 8 段 / 800 字）且长段落优先；其余批次等首批出首字再并发，让前缀缓存先建好。
- 后续批次按 `ProviderGate` 的**空闲通道**切分（`laneBatchChars`），通道忙时批次变大，避免把大量单段请求排进队列。按 RPM 限流的免费档保持整批。
- `ProviderGate`（每个服务商一个，所有标签页共享）：并发上限、可选 RPM 窗口、收到 429/503/529 时按 `Retry-After` 暂停并减半并发一分钟；连续两次限流触发熔断。
- 备用服务商：主服务商出错时最多重试一次就转给备用；首字 8 秒未到也转（排队中可取消）。

### 校验与降级
- 本地校验：段落 ID 完整、占位符、长度比、未翻译、夹在中文里的英文虚词、术语。
- 严重程度分级：丢 `{{n}}` 原子是硬失败；丢链接是软失败（重试一次）；丢格式标签直接接受。
- 降级阶梯：整批 → 半批 → 逐段 → 去标签纯文本 → 报错（可点击重试）。
- 中英文空格、全角标点、弯引号在本地处理（`polishChinese`），不依赖模型。

### 渲染
- 译文放在 `<xt-trans>` 里；只看译文模式把原文包进 `<xt-orig>`。切换模式只改根元素的 class。
- 布局守卫：导航高度增长过多、固定高度容器溢出、轮播内的长段落，退为悬停提示。
- 模型输出只作为文本节点插入，从不解析为 HTML。

### 内嵌页面（iframe）
- 有的网站把整个正文放进一个铺满窗口的 iframe（例如 Google 开发者文档的部分页面）。内容脚本在所有框架里加载，但子框架只在「是页面本身」时参与（`src/content/frames.ts`）：至少 500×400、不是编辑器（`designMode` 或可编辑的 body）、不是广告 / 验证码 / 支付 / 视频 / 社交挂件 / 登录服务的域名。小框架什么都不做，也不连接后台；加载后才被撑大的框架在尺寸达标时再参与。
- 子框架从不自己开始翻译：只有用户为这个页面开启了翻译（弹出菜单、快捷键、右键菜单），或这个网站设为「总是翻译」时才开始；全局「自动翻译」只作用于顶层文档。
- 框架里出现能识别的登录或支付输入框（`sensitiveFrame`：密码框、`autocomplete` 的一次性验证码 / 银行卡字段，以及名称、id、标签或提示文字像验证码、卡号、安全码、有效期的输入框）时：Controller 不能启动（`canStart`），传输层除 `reset` 外什么都不发（内部重启、精翻、重试、预处理都经过它），MutationObserver 发现这类字段出现时立即停止已开始的翻译；这样的框架也不计入弹出菜单的状态。
- 用户对页面的选择（开关、显示方式、场景专家）只有一个来源：顶层文档（`src/content/page-intent.ts`）。页面级命令只发给顶层文档，它按自己的状态依次执行（连按两次 Alt+A / Alt+S 也不会读到过期状态），记下结果并让版本号加一，在回复里带上新的结果；发命令的一方（弹出菜单或后台）再用 `scripting.executeScript` 把它写进所有框架，返回即表示各框架已执行（`src/shared/tab-state.ts`）。框架只应用自己所属顶层文档（每个顶层文档启动时生成随机标识）的、比已有版本更新的结果，所以乱序、重复或导航前的旧结果都不会生效；顶层还没回答过时，框架什么都不应用、也不按收到的结果猜测自己属于哪个页面，而是在收到更新时重新询问；框架忽略直接广播来的页面级命令。写入后发命令的一方再读一次状态，读取标签页状态时（包括弹出菜单打开期间每次轮询）版本落后的框架会被补发最新结果；框架获得焦点或变为可见时也会向顶层重新询问，所以一次更新丢失不需要用户再操作就能恢复。新加载或导航的框架先暴露接收函数、再向顶层询问当前结果（`frame-join` → `page-intent`），之后的变化以更新的版本到达。顶层文档初始化失败（例如读取设置失败）时，等待中的请求立即得到空回复，之后的请求也不再挂起。用户点了「显示原文」，新框架也保持关闭。
- 站点规则的「总是 / 从不翻译」在子框架里按顶层网站判断（`location.ancestorOrigins`），CSS 选择器仍按框架自己的网站。
- 每个参与的文档各有自己的会话。弹出菜单用 `scripting.executeScript`（allFrames）读取各文档在扩展隔离环境里暴露的状态，合并成一页（`src/shared/frame-state.ts`、`tab-state.ts`）：任一文档开启即算「已开启」（「显示原文」和 Alt+A 总能恢复整页）；还有文字的文档没开启时（例如全局自动翻译只开了顶层），弹出菜单另外显示「内嵌页面里还有约 N 段未翻译」和「翻译内嵌页面」。精翻当前选中、重试失败段落、清除缓存这类按文档的命令发给所有文档，「精翻此段」只发给打开右键菜单的那个框架；只有顶层文档回复。不需要新增权限。
- 一段可翻译的文字都没有时，弹出菜单显示「这个页面没有找到可翻译的文字」，不再显示「等待页面滚动」。

### 短文本与免费机翻
- 可把按钮、菜单这类短文本交给谷歌 / 微软的免费接口（非公开接口，默认关闭）。
- 只交给机翻：不含标签、术语、名称的普通界面短语。科技场景、署名、@用户名、字母数字混写、缩写一律走 LLM。机翻失败时回退到正文服务商。

## 站点语言包

为没有用户语言的网页应用（如 AI 聊天应用）生成可复用的界面译文。

### 隐私边界
1. 收集范围有两种：`auto`（默认，由 `classify.ts` 判断界面还是内容）和 `regions`（只读用户圈选的区域，v1 语言包迁移后保持这一授权）。
2. `classify.ts` 的优先级：硬性隐私标记（邮箱、指向单个条目的链接、@用户名等，直接丢弃）→ 用户排除 → 正文容器（编辑器、对话记录、文档）→ 账户区（头像或缩写触发器本身不收集，其菜单只收菜单项）→ 用户条目列表（带每行操作菜单、头像或时间的行或卡片，一两张也算；导航与选项列表除外）→ 界面信号。内容只计数、不保存；不确定的默认不勾选并写明原因。应用译文时也会再检查一遍，不把界面译文写进内容里。
3. 结构标签（分区名、问题标签）在 `structure.ts` 里就会剔除像个人信息的文字；发送给模型的结构上下文只使用已批准的文字（`units.approvedLabels`）。
4. 审核页预览**将要发送的完整请求**，预览冻结成 `planId`，生成只接受这个 `planId`，与真实请求使用同一个构建函数；mock 服务端在 e2e 里核对实际收到的请求。
5. 候选区 30 天过期，不导出、不自动发送；导出前清洗（`scrubForExport`，含位置标签和术语）并预览。

### 界面结构与语境（`structure.ts`）
- 节点：surface（页面、对话框、菜单、下拉列表、弹出层）› section › group › item。导航集合按容器识别：一个容器里有 3 个以上控件、恰好一个处于激活状态；Claude 那种 `ul > li > button` 的「表兄弟」结构和不在 `nav` 里的 hub 链接都能识别。导航只管它后面的内容。
- 分组：先找外层分组的标签（问题），再看控件本身，所以「用当前值给自己命名」的下拉框（职业 Engineering）归到外层问题下；弹层用触发器所在的问题命名，而不是触发器的当前值。
- 语境签名：`g:` = fnv(分区 | 分组角色 | 分组标签)，`s:` = fnv(界面类型 | 界面标签 | 分区 | 角色)。不含兄弟选项，因为它们会延迟挂载。读取的都是原文（registry 的 `origText` / `origAttr`），页面翻译后签名不变。
- 同一原文在不同语境译法不同时，存为按语境区分的变体；只有变体的原文遇到没见过的语境时保持原文，并作为「新语境」进入候选区，不静默套用。
- 应用器跟踪按语境翻译的节点，所在 surface 或地标变化时重新校验（处理虚拟列表复用节点「文字没变、语境变了」的情况）；新修订原地更新，不先还原；遍历可续传，每 32 个节点检查一次 8ms 预算。

### 一键扫描（`explorer.ts`、`scan.content.ts`）
- 只碰导航项和展开类控件；选项、菜单项（设置链接除外）、开关、复选框、单选、滑块、输入框、表单控件、外站链接、危险词标签一律不碰。
- 动作协议：导航项一次 `click()`，并验证激活标记转移或地址变化；弹层先 `click()`，没打开再派发一次完整的 `pointerdown`（Radix、Base UI）。关闭时先在触发器上重复打开时的操作；不行再用 Escape，先在 `<body>` 拦截冒泡，再用普通 Escape。不同库叠在一起时 Escape 会把父对话框一并关掉，这个顺序就是为此设计的。
- 子页面：同源的子路径和设置页链接。应用没有接管的链接点击会被取消，页面永远不会整页跳转。只有确认刚好 push 了一条历史记录（用 Navigation API 的 entry index 判断）时才用 `history.back()` 回退。
- 状态护栏：每一步后比较前后都存在的设置控件的值，发现变化立即中止并恢复；新挂载的控件在这时记下基准值。
- 授权：后台给每次扫描发 `scanId` 和 nonce，并绑定标签页、`documentId` 和 host；浮层拦截用户的鼠标和键盘事件，Esc 可停止；有未保存输入的对话框会拒绝扫描。
- 测试页使用真实的 Base UI / Radix 组件（`e2e/fixtures/claude-like.tsx`、`devin-like.tsx`）。

### 日常学习（`learner.ts`）
- 由应用器的 miss 触发，在空闲时处理：分类（内容不收）、描述结构、限速（每分钟 60 条、每次页面加载 300 条），扫描期间暂停。只有开启了 `options.learn` 并且是自动范围时才会超出圈选区域。

### 格式（`src/pack/format.ts`）
- `translucid-site-pack` v2：`site{hosts,scopes,name,description}`、`regions`、`targetLang`、`glossary`、`entries[{kind,src,t,status,ctx?,where?}]`、`contexts`（每条原文出现过的语境）、`surfaces`、`excludes`、`options{hydration,learn,scope}`、`rev`。v1 文件和已安装数据在后台启动时幂等迁移（`migrateInstalled`）。
- 每条原文最多 8 个语境变体；运行时形式里 `map` 存通用译文，`ctx` 存按语境的译文，`ambiguous` 列出只有变体的原文。
- 条目身份为 `kind + 规范化原文`（NFC、去 ZWSP/BOM、折叠 ASCII 空白，保留 ZWJ/ZWNJ/NBSP）。
- 导入与生成结果走同一套严格校验：未知字段丢弃、控制字符与 bidi 覆盖字符剔除、不得含标签、占位符一致、长度上限。

### 运行时
- `pack.content.ts` 以 `registration: 'runtime'` 构建，后台用 `scripting.registerContentScripts` 只为有语言包的 host 注册（差异对账、`persistAcrossSessions`），已打开的标签页按需注入。
- 依赖受测试约束：只能引用 `wxt/browser`、`src/pack/*` 和极小的共享模块。
- 应用器只改 `Text.data` 和已有属性，不移动、不增删节点；记录原值以便精确还原；按「当前值是否等于我们写入的值」判断归属，框架重渲染后自动重新应用；每次回调有 8ms 预算；改写过频的节点交还给页面。
- 每个 open shadow root 单独监听。
- 服务端渲染的页面默认等 `load` 后 DOM 稳定再应用（fail-closed），可按语言包改为立即应用。
- 文章翻译器通过共享注册表跳过语言包接管的节点（含子孙），并作废相关段落。

### 生成（`pack-gen.ts`、`units.ts`、`prompt/ui-locale.ts`）
- 只有「答案」（选项、单选、下拉当前值等依赖所属问题的文字）按语境分开翻译，其余文字在所有出现处共用一条译文。
- 问题单元（问题标签、说明、当前值、全部选项）不拆分到不同批次；超大的分组拆开时，每一段都带上问题标签和兄弟选项作为只读上下文。重试也一样，不会把 Engineering 单独丢给模型。
- 提示词 v2 的 `<strings>` 是一份缩进大纲：界面 › 分区 › 问题 › 元素，角色词写在标签外，id 按显示顺序递增。
- 回复严格解析（只接受闭合的 `<n>`，重复 ID 整条拒收）。首批单独发送，之后最多 4 条通道并行；每批在 store 事务（`mutatePack`）里合并，并校验任务身份，取消后迟到的响应会被丢弃，**不覆盖用户编辑过的条目**。语言包被删除时任务停止。
- service worker 重启后任务变为「已暂停」，由用户选择继续或取消。
- 与网页翻译共享 `routing.ts` 的限流、备用和熔断；不使用机翻。

## 测试

- `pnpm test`：Vitest + happy-dom 单元测试（提取、校验、调度、限流、格式、隐私、应用器、生成任务等）。
- `pnpm e2e`：Playwright 在真实 Chromium 中加载 `dist/chrome-mv3`，使用本地 fixture 页面（静态页、React、模拟 SSR、shadow DOM、虚拟列表，以及用真实 Base UI / Radix 写的 claude-like、devin-like 测试页）和本地 mock LLM（`e2e/mock-llm.mjs`，在服务端记录收到的请求）。覆盖的流程：语言包的注册、应用和还原；一键扫描（覆盖率、不改设置、恢复原状、拒绝草稿、停止、拦截用户输入、子页面）；圈选 → 审核 → 预览 → 生成；独立页面完整流程；扩展重启后的暂停和继续。
- `pnpm build:debug` 构建调试版，内含页面调试接口（`window.postMessage({xtDebug: …})`）。正式版不含调试接口，由 e2e 检查产物。语言包相关的调试命令只在设置页「调试域名」列出的站点生效。

## 已知限制

- 网页段落翻译的目标语言固定为简体中文；站点语言包支持任意目标语言。
- 语言包不处理 closed shadow DOM、canvas 文字、跨域 iframe；同源 iframe 暂不支持。
- 语言包只做整串精确匹配：不处理拆分到多个文本节点的字符串和数字模板（如「3 messages」）。同形词按界面语境区分（见上），但同一分组内两处相同文字视为同一语境。
- 一键扫描只从当前状态出发：设置窗口需要用户先打开（菜单里的「设置」菜单项不会被自动点击）；预算是 120 次操作、120 秒。
- RTL 目标语言只替换文字，不镜像布局。
